The Pattern: Self-Scheduling Stacks

  Your ReactionPQ is already the right tool. The key idea is a stack that re-pushes itself after resolving.

  Step 1 — Define the ability in CardDef

  Add a RecurringAbility type so the definition is data-driven rather than hardcoded:

  // defs/cardDef.go
  type RecurringAbility struct {
      IntervalMs int64
      Effects    []state.Effect
  }

  type CardDef struct {
      // ...existing fields...
      RecurringAbilities []RecurringAbility
  }

  // Card 3: Matter of Time
  3: {
      ...
      RecurringAbilities: []RecurringAbility{
          {IntervalMs: 20000, Effects: []state.Effect{{Type: state.EffectMana, A: -1, B: 1}}},
          // A: -1 = "card's own team", B: 1 = amount
      },
  },

  Step 2 — Tag StackEntry with the interval

  // state/StackPQ.go
  type StackEntry struct {
      Type               int
      CardID             int
      PopTime            int64
      Effects            []Effect
      RecurringIntervalMs int64  // non-zero = recurring
  }

  Step 3 — Kick off the first trigger on summon

  In SimulateStack, inside the SummonResolution case, after placing the card on the field, check its CardDef for
  recurring abilities and push the first stack:

  case state.SummonResolution:
      // ...existing summon log...

      // schedule recurring abilities
      def := defs.CardDefs[gs.Cards[topEntry.CardID].DefNo]
      for _, ra := range def.RecurringAbilities {
          heap.Push(&gs.ReactionPQ, &state.Stack{
              PopTime: time.Now().UnixMilli() + ra.IntervalMs,
              StackEntries: []state.StackEntry{{
                  Type:                6, // recurring ability
                  CardID:              topEntry.CardID,
                  PopTime:             time.Now().UnixMilli() + ra.IntervalMs,
                  Effects:             ra.Effects,
                  RecurringIntervalMs: ra.IntervalMs,
              }},
          })
      }

  Step 4 — Handle the trigger: apply effect, then re-schedule

  Add a new case in SimulateStack for Type == 6:

  // after the existing effect switch, before removing the stack entry:
  if topEntry.Type == 6 {
      card := gs.Cards[topEntry.CardID]
      if card.Zone == state.ZoneField {
          // re-schedule the next trigger
          nextTime := time.Now().UnixMilli() + topEntry.RecurringIntervalMs
          heap.Push(&gs.ReactionPQ, &state.Stack{
              PopTime: nextTime,
              StackEntries: []state.StackEntry{{
                  Type:                6,
                  CardID:              topEntry.CardID,
                  PopTime:             nextTime,
                  Effects:             topEntry.Effects,
                  RecurringIntervalMs: topEntry.RecurringIntervalMs,
              }},
          })
      }
      // if card is off the field (destroyed, etc.), we just don't re-push — ability stops naturally
  }

  And handle EffectMana in the effect switch:
  case state.EffectMana:
      teamIndex := gs.Cards[topEntry.CardID].Team
      if currentEffect.A == -1 { // own team
          gs.Mana[teamIndex] += currentEffect.B
      } else {
          gs.Mana[currentEffect.A] += currentEffect.B
      }

  ---
  Why this works cleanly

  - No separate goroutine or ticker — it lives entirely in the PQ you already have.
  - Auto-stops on destruction — when "Year Zero" destroys Matter of Time, the next time the recurring stack fires,
  card.Zone != ZoneField, so it simply doesn't re-push.
  - DeepCopyGameState already handles it — since it deep-copies the PQ, recurring stacks survive state copies correctly.
  - Scales to any card — any card with RecurringAbilities in its CardDef gets the behavior for free
