SESSION SUMMARY - fd3 log redesign
====================================

CONTEXT
-------
The frontend replays the game simulation from logs the backend sends. The game state
has changed and the logs need to catch up. The frontend is in a separate TypeScript repo.

THE CORE PROBLEM
----------------
The frontend mirrors the backend game state but does NOT mirror the ReactionPQ (priority
queue of stacks). So when the full game state is sent (e.g. on client refresh), the
frontend sees scheduled effects in the PQ but has no way to remove them when they resolve,
because the logs never told it they were scheduled in the first place.

Every PQ mutation (push AND pop) needs a corresponding log entry so the frontend can
mirror the PQ exactly.

THE SOLUTION
------------
Instead of duplicating scheduling logic (fulfillEffectTemplate etc.) in TypeScript,
emit a log entry for every PQ push so the frontend just executes instructions.
This keeps all scheduling rules on the backend.

This means:
- ScheduleDrawCard should emit a log (replaces the previously discussed DrawScheduled log type)
- DeclareCard / fulfillEffectTemplate should emit a log for each Stack pushed to the PQ
- SummonResolution (and other resolves) should signal the frontend to remove the entry from its local PQ

FOG OF WAR NOTE
---------------
The architecture supports fog of war: emit the log on declare, but filter the broadcast
per client. On reveal/resolve, broadcast to everyone. Not implementing now, just good to know it fits.

LOG STRUCTURE REDESIGN
----------------------
Current: EventLog []logs.Log  (flat struct with A, B, C int fields)

Problem: ScheduledStack needs nested variable-length data ([]StackEntry, each with []Effect),
which doesn't fit the flat struct.

Decision: Change EventLog to []any, holding two struct types:
  1. Log (existing flat struct) - for simple events like PhaseLog, DrawExec, DeclareCard, SummonUnit
  2. ScheduledStack (new struct) - for PQ push events

Both structs have a Type LogType field (the existing iota enum). The enum value tells
you which struct you're dealing with when you pull it out of the slice. Add a new enum
value: ScheduleEffect.

New structs to add to EventLog.go:

    type ScheduledStack struct {
        Timestamp    int64
        UpdateID     int
        Type         LogType
        PopTime      int64
        StackEntries []ScheduledEntry
    }

    type ScheduledEntry struct {
        Type    int
        CardID  int
        Effects []state.Effect  // reuse existing Effect struct
    }

And change:
    EventLog []logs.Log
to:
    EventLog []any

FIRST FILE TO TOUCH
-------------------
engine/logs/EventLog.go

THEN

- fulfillEffectTemplate: add eventLogs param, emit ScheduledStack log per heap.Push
