PLAN: Remove dead unit abilities from ReactionPQ on death
==========================================================

PROBLEM
-------
When a unit dies (EffectDestroy in ManageStackPQ.go), its Zone is set to ZoneGraveyard
and it's moved to gs.Grave, but any future Stacks in ReactionPQ that belong to that
unit (e.g. recurring abilities, type 6) are left in the queue and will still fire.

The fix has two parts:


PART 1 — Add RemoveStacksByCardID to PriorityQueue (engine/state/StackPQ.go)
------------------------------------------------------------------------------
Add this method at the bottom of StackPQ.go:

    func (pq *PriorityQueue) RemoveStacksByCardID(cardID int) []*Stack {
        var removed []*Stack
        kept := pq.Items[:0]

        for _, stack := range pq.Items {
            filtered := stack.StackEntries[:0]
            for _, entry := range stack.StackEntries {
                if entry.CardID != cardID {
                    filtered = append(filtered, entry)
                }
            }
            stack.StackEntries = filtered

            if len(stack.StackEntries) == 0 {
                stack.index = -1
                removed = append(removed, stack)
            } else {
                kept = append(kept, stack)
            }
        }

        pq.Items = kept
        heap.Init(pq)   // re-heapify after bulk removal
        return removed  // caller uses these to emit RemoveStack logs
    }

Notes:
- Iterates all stacks, filters out StackEntries belonging to cardID.
- If a stack has no entries left, it's considered fully removed.
- If a stack still has entries from other cards (future chain responses etc.), it stays.
- Uses heap.Init to re-establish the heap invariant after bulk mutation.
  heap.Init calls Swap internally, which keeps all .index fields correct.
- Returns removed stacks so the caller can log them.


PART 2 — Call it inside EffectDestroy (engine/randomFunctions/ManageStackPQ.go)
---------------------------------------------------------------------------------
Inside the EffectDestroy case, after setting a card's Zone to ZoneGraveyard,
call RemoveStacksByCardID for that card and emit a RemoveStackLog per removed stack.

Current code (lines ~122-130):

    for a := 0; a < len(gs.Field); a++ {
        for b := 0; b < len(gs.Field[a]); b++ {
            cardIndex := gs.Field[a][b]
            gs.Cards[cardIndex].Zone = state.ZoneGraveyard
            gs.Grave[a] = append(gs.Grave[a], cardIndex)
        }
        gs.Field[a] = []int{}
    }

Change to:

    for a := 0; a < len(gs.Field); a++ {
        for b := 0; b < len(gs.Field[a]); b++ {
            cardIndex := gs.Field[a][b]
            gs.Cards[cardIndex].Zone = state.ZoneGraveyard
            gs.Grave[a] = append(gs.Grave[a], cardIndex)

            for _, s := range gs.ReactionPQ.RemoveStacksByCardID(cardIndex) {
                *logList = append(*logList, logs.RemoveStackLog{
                    UpdateID:  *UpdateID,
                    Timestamp: topEntry.PopTime + constants.LEAD,
                    Type:      logs.RemoveStack,
                    StackID:   s.StackID,
                })
                *UpdateID += 1
            }
        }
        gs.Field[a] = []int{}
    }

Note: RemoveStacksByCardID is called per card (inner loop), not per team (outer loop),
so it runs once for each dying unit.


EDGE CASES TO CONSIDER LATER
------------------------------
- EffectDestroy currently only handles "destroy all" (A==0). When team-specific or
  card-specific destroy is added, the same cleanup needs to happen for each killed card.
- The currently-executing Stack (stackHeader) is still in pq.Items[0] while
  SimulateStack runs. If a self-destruct scenario causes the active stack's card to be
  destroyed, RemoveStacksByCardID could remove entries from the live stack. In practice
  this shouldn't happen since destroy spells come from spell cards (type 5), not from
  recurring unit abilities — but worth keeping in mind.
